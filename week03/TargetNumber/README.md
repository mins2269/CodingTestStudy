# [프로그래머스] 타겟 넘버

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/43165
- 난이도: Lv.2
- 유형: 깊이/너비 우선 탐색(DFS/BFS)

## 문제 요약
음이 아닌 정수 배열 `numbers`가 주어진다. 각 숫자의 순서는 바꾸지 않고 **더하거나 빼서** `target`을 만드는 방법의 수를 구하는 문제.

## 내 풀이 (Solution.java)
- 접근 방법
    - 각 숫자마다 `+` 또는 `-` 두 가지 선택지가 있으므로, 모든 경우를 DFS로 완전탐색한다.
    - 재귀 함수에 **현재 인덱스(`idx`)와 지금까지의 합(`sum`)** 을 매개변수로 넘긴다.
        - `dfs(idx + 1, sum + numbers[idx])` : 현재 숫자를 더하는 경우
        - `dfs(idx + 1, sum - numbers[idx])` : 현재 숫자를 빼는 경우
    - 모든 숫자를 사용했을 때(`idx == numbers.length`) 합이 `target`과 같으면 개수를 1 증가시킨다.
- 시간복잡도
    - 숫자마다 2갈래로 나뉘므로 **O(2ⁿ)**
    - `n ≤ 20`이므로 최대 약 100만 번으로 충분히 통과한다.
    - 재귀 깊이는 n이므로 공간복잡도는 **O(n)**

## 더 나은 풀이
- 개선점: 전역 변수 대신 **반환값으로 개수를 합산**하면 상태 관리가 필요 없고 초기화 실수도 막을 수 있다.
    ```java
    static int dfs(int[] numbers, int target, int idx, int sum) {
        if (idx == numbers.length) return sum == target ? 1 : 0;
        return dfs(numbers, target, idx + 1, sum + numbers[idx])
             + dfs(numbers, target, idx + 1, sum - numbers[idx]);
    }
    ```
- 큐를 사용해 BFS로도 풀 수 있다. 레벨마다 "지금까지 가능한 합"들을 큐에 넣고, 꺼낼 때 `+num`, `-num` 두 값을 다시 넣는다. 시간복잡도는 O(2ⁿ)로 같지만, 마지막 레벨에서 큐에 2ⁿ개가 쌓이므로 메모리는 DFS보다 더 쓴다.
- 합의 범위가 작다면(숫자 ≤ 50, n ≤ 20 → 합은 -1000 ~ 1000) **`(인덱스, 합)` 기준의 DP/메모이제이션**으로 같은 상태의 중복 계산을 없애 **O(n × 합의 범위)** 로 줄일 수 있다.

## 배운 점
- 처음엔 숫자를 큐에 담고 `poll()`하며 재귀를 돌렸는데, **하나의 큐를 모든 재귀 호출이 공유**해서 첫 번째 갈래(`-num`)가 남은 숫자를 전부 꺼내버렸다. 그 결과 두 번째 갈래(`+num`)는 빈 큐를 받아 탐색이 제대로 되지 않았다.
    - `poll()`은 요소를 **실제로 제거**하므로 되돌아가서 다른 선택을 하는 백트래킹과 맞지 않는다.
    - DFS에서는 공유 자료구조를 변경하기보다 **인덱스처럼 각 호출이 독립적으로 가지는 값을 매개변수로** 넘기는 것이 안전하다.
- 원소마다 선택지가 2개인 문제는 **2ⁿ 완전탐색**이며, n의 제한(여기선 20)을 보고 가능 여부를 먼저 판단한다.
- 기저 조건은 "모든 숫자를 다 썼을 때"이고, 그때만 `target`과 비교해야 한다. 중간에 합이 같아졌다고 세면 안 된다.
- static 카운터를 쓴다면 `solution` 시작 시 **0으로 초기화**해야 여러 테스트 케이스에서 값이 누적되지 않는다.
