# [프로그래머스] 구명보트

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42885
- 난이도: Lv.2
- 유형: 탐욕법(Greedy)

## 문제 요약
사람들의 몸무게 배열(`people`)과 구명보트의 무게 제한(`limit`)이 주어진다. 보트에는 **최대 2명**까지 탈 수 있고, 두 사람의 몸무게 합이 `limit` 이하여야 한다. 모든 사람을 구출하기 위해 필요한 구명보트 개수의 **최솟값**을 구하는 문제.

## 내 풀이 (Solution.java)
- 접근 방법
    - 몸무게를 오름차순으로 **정렬**한다.
    - 가장 가벼운 사람(`left`)과 가장 무거운 사람(`right`)을 가리키는 **투 포인터**를 양 끝에 둔다.
    - `left <= right`인 동안 반복한다.
        - 두 사람의 합이 `limit` 이하이면: 둘이 함께 탑승 (`left++`)
        - 가장 무거운 사람은 짝이 있든 없든 항상 탑승 (`right--`)
        - 보트 하나 사용 (`answer++`)
    - `left == right`인 경우(한 명만 남음)도 반복 조건에 포함되므로 보트 하나로 처리된다.
- 그리디가 성립하는 이유
    - 가장 무거운 사람은 어차피 보트 하나를 써야 한다.
    - 그 사람과 같이 탈 수 있는 사람이 있다면 **가장 가벼운 사람**과 짝짓는 것이 항상 유리하다.
    - 가장 가벼운 사람과도 함께 탈 수 없다면 누구와도 탈 수 없으므로 혼자 보낸다.
- 시간복잡도
    - 정렬 O(n log n) + 투 포인터 순회 O(n) → **O(n log n)**

## 배운 점
- "최대 2명씩 묶어서 개수를 최소화"하는 문제는 **정렬 후 양 끝에서 짝짓는 투 포인터**로 단순화된다.
- 매 반복에서 `right--`와 `answer++`는 무조건 실행하고, 짝이 맞을 때만 `left++`를 하면 분기 없이 깔끔하게 구현할 수 있다.
- 반복 조건을 `left < right`가 아닌 `left <= right`로 두어야 마지막에 혼자 남은 사람까지 보트에 태울 수 있다.
- 무거운 사람부터 처리하는 이유를 "가장 무거운 사람은 반드시 보트 하나를 쓴다"는 관점으로 정리하면 그리디의 정당성을 설명하기 쉽다.
