# [프로그래머스] 조이스틱

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42860
- 난이도: Lv.2
- 유형: 그리디

## 문제 요약
주어진 알파벳 이름을 바탕으로 조이스틱 각 방향으로 몇 번 움직이는 것이 가장 저렴한지

## 내 풀이 (Solution.java)
- 접근 방법
    - 알파벳 변경 비용과 커서 이동 비용을 **따로 계산**해서 더한다.
    - 알파벳 변경 비용: 글자마다 위로 갈지 아래로 갈지 중 작은 쪽을 고른다. (`Math.min(weight, 26 - weight)`)
    - 커서 이동 비용: 바꿔야 할 위치(`A`가 아닌 칸)를 리스트(또는 비트마스크)에 1/0으로 표시하고, 커서를 **왼쪽 한 칸 / 오른쪽 한 칸**으로 재귀(`shiftLeft`, `shiftRight`)하며 **모든 경우를 완전탐색**한다.
    - 새 칸에 도착하면 방문 처리(1 → 0)하고, 남은 칸이 없으면 이동 횟수의 최솟값을 갱신한다.
    - 두 방향이 같은 상태를 공유하지 않도록 백트래킹(되돌리기)이나 값 복사가 필요하다.
    - 제자리를 맴도는 경로를 막기 위해 `moves >= best` 가지치기와 `(위치, 남은 상태)` 메모가 필요하다.
- 시간복잡도
    - 가지치기·메모가 없으면 최악의 경우 이동 횟수에 대해 매번 2갈래로 나뉘므로 **O(2^n)**
    - `(위치, 남은 상태)` 메모를 쓰면 방문한 칸이 항상 시작점을 포함한 연속 구간이라 상태 수가 다항식 수준(최대 약 O(n³))으로 줄어든다.
    - 이름 길이가 최대 20이라 통과는 가능하지만 구현이 복잡하고 실수하기 쉽다.

## 더 나은 풀이 (BetterSolution.java)
- 개선점: 매 단계 "왼쪽/오른쪽"을 고르는 완전탐색 대신, **의미 있는 이동 경로가 두 가지 모양뿐**이라는 구조를 이용해 각 위치 `i`를 한 번씩만 계산한다. 재귀, 방문 배열, 메모가 모두 필요 없어진다.
- 접근 방법
    - 알파벳 변경 비용은 내 풀이와 같다.
    - 커서 이동은 **오른쪽으로 `i`번째 칸까지 방문**하고, `i` 뒤에 이어지는 `A` 구간을 건너뛴 첫 위치 `next`부터 끝까지는 **왼쪽으로 돌아가서 방문**하는 경로로 한정한다.
    - `back = n - next`라고 하면, 먼저 가는 쪽이 왕복(2번 지나감)이다.
        - 오른쪽 먼저: `2 * i + back`
        - 왼쪽 먼저: `i + 2 * back`
    - move는 쭉 가는 경우, a는 오른쪽으로 갔다가 되돌아와서 왼쪽으로 가는 경우, b는 왼쪽으로 출발해서 다시 되돌아와서 오른쪽으로 가는 경우
    - 기준선은 오른쪽으로만 끝까지 가는 `n - 1`이고, 모든 `i`에 대해 위 값들과 비교해 최솟값을 고른다.
    - 최종 답 = 알파벳 변경 비용의 합 + 커서 이동 최솟값
- 시간 복잡도
    - 알파벳 변경 비용: O(n)
    - 커서 이동: 모든 `i`마다 `next`를 찾는 반복이 있어 **O(n²)** (다음 `A`가 아닌 위치를 미리 구해 두면 O(n)까지 줄일 수 있다.)

## 배운 점
- 두 종류의 비용(알파벳 변경, 커서 이동)이 서로 영향을 주지 않으면 **나눠서 계산**하면 문제가 단순해진다.
- 완전탐색으로 풀 때는 재귀 호출끼리 **상태를 공유하지 않도록** 값 복사나 백트래킹이 필요하고, 같은 상태를 다시 계산하지 않도록 **가지치기와 메모**가 필요하다.
- 원형 이동은 `(pos + d + n) % n`으로 쓴다. `n`을 더하는 이유는 자바에서 음수 `%`가 음수를 반환하기 때문이다.
- 바꿔야 할 위치처럼 "있다/없다"만 표시하는 상태는 비트마스크(`|=`로 켜기, `& ~`로 끄기)로 표현할 수 있다.
- "가장 가까운 칸부터 이동"하는 단순한 그리디는 틀린다. 이 문제의 그리디는 알파벳 변경 부분이고, 커서 이동은 **경로의 모양을 좁힌 뒤 모든 후보 중 최솟값을 고르는 방식**이다.
- 완전탐색으로 먼저 풀어 본 뒤 "경로가 어떤 모양으로 한정되는가"를 찾아내면 최적화할 수 있다.
