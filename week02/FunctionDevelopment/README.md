# [프로그래머스] 기능개발

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/42586
- 난이도: Lv.2
- 유형: 스택/큐

## 문제 요약
각 기능의 현재 진도(`progresses`)와 하루 개발 속도(`speeds`)가 주어진다. 뒤에 있는 기능이 먼저 100%가 되어도 앞 기능이 배포될 때 함께 배포된다. 이때 각 배포마다 몇 개의 기능이 배포되는지 순서대로 구하는 문제.

## 내 풀이 (Solution.java)
- 접근 방법
    - 각 기능이 완료되기까지 걸리는 날짜를 먼저 계산한다. `days = ceil((100 - progress) / speed)`
    - 앞에서부터 순회하며 현재 배포의 **기준 날짜**(그 배포에 포함된 기능 중 가장 늦게 끝나는 날)를 들고 간다.
        - 기능의 완료일이 기준 날짜 이하이면: 같은 배포에 포함 (개수 +1)
        - 기능의 완료일이 기준 날짜보다 크면: 지금까지의 개수를 결과에 저장하고, 이 기능을 기준으로 **새 배포**를 시작
    - 마지막 배포의 개수는 반복문이 끝난 뒤 따로 저장한다.
- 시간복잡도
    - 모든 기능을 한 번씩만 보므로 **O(n)**

## 더 나은 풀이
- 개선점: 올림 계산을 실수 연산(`Math.ceil`) 대신 **정수 연산**으로 처리하면 부동소수점 오차를 걱정하지 않아도 된다.
    - `days = (100 - progress + speed - 1) / speed`
- 큐를 사용해 "맨 앞 기능의 완료일 이하인 기능들을 모두 꺼내는" 방식으로도 풀 수 있다. 시간복잡도는 같은 O(n)이다.

## 배운 점
- 순서가 중요한 배포 문제는 **완료일 배열로 바꾼 뒤** 앞에서부터 "기준 날짜보다 큰 값이 나올 때마다 끊는" 방식으로 단순화된다.
- 올림은 `(a + b - 1) / b`로 정수 연산만으로 구할 수 있다.
- 마지막 그룹은 반복문 안에서 저장되지 않으므로, **반복문 종료 후 마지막 그룹을 따로 추가**하는 것을 잊지 말아야 한다.
- 결과 개수를 미리 알 수 없으므로 `List<Integer>`에 담았다가 `int[]`로 변환한다.
