# [프로그래머스] 불량 사용자

- 링크: https://school.programmers.co.kr/learn/courses/30/lessons/64064
- 난이도: Lv.3
- 유형: 완전탐색

## 문제 요약
응모자 아이디 목록(`user_id`)과 불량 사용자 아이디 패턴 목록(`banned_id`, `*`는 어떤 한 글자와도 일치)이 주어질 때, 제재 아이디 목록으로 가능한 **경우의 수**를 구한다. 제재 아이디 목록은 **순서와 상관없이 구성이 같으면 같은 경우**로 본다.

## 내 풀이 (Solution.java)
- 접근 방법
    - `banned_id`의 각 패턴마다 일치하는 `user_id`의 **인덱스 후보 목록**을 만든다.
        - 길이가 다르면 바로 제외하고, 길이가 같으면 글자를 하나씩 비교한다. (`*`이거나 같은 글자여야 일치)
        - 후보 목록은 패턴당 **하나의 리스트**로 만든다. 예: `fr*d*` → `[0, 1]`, `abc1**` → `[3]`
    - "지금까지 고른 사용자 집합"을 **상태**로 두고, 패턴을 하나씩 처리하며 상태를 확장한다.
        - 시작 상태는 아무것도 안 고른 **빈 집합 하나** (`{ {} }`)
        - 각 패턴의 후보 중 **이미 집합에 있는 사용자는 제외**하고 하나를 추가해 새 집합을 만든다.
    - `Set<Set<Integer>>`에 담으면 원소가 같은 집합(순서만 다른 경우)은 **자동으로 하나로 합쳐진다.**
    - 모든 패턴을 처리한 뒤 상태의 개수가 정답이다.
- 시간복잡도
    - `user_id`와 `banned_id`가 최대 8개이므로 집합의 개수는 최대 2^8 이하
    - 패턴마다 (상태 수 × 후보 수)만큼 확장하므로 이 제한에서는 충분히 통과한다.

## 더 나은 풀이
- 개선점: 집합을 `Set<Integer>`가 아닌 **비트마스크(`int`) 하나**로 표현한다.
    - `user_id`가 최대 8개이므로 `int` 하나로 충분하다.
    - 상태: `mask` (i번째 비트가 1이면 i번째 사용자를 이미 제재 목록에 넣음)
    - 후보 추가: `if ((mask & (1 << idx)) == 0) next.add(mask | (1 << idx));`
    - `Set<Set<Integer>>`보다 객체 생성과 해시 계산이 훨씬 적어 빠르고 간결하다.
- 같은 아이디어를 **DFS + 백트래킹**으로 풀어 마지막에 비트마스크를 `Set<Integer>`에 모으는 방법도 있다.

## 배운 점
- "순서는 상관없고 구성만 같으면 같은 경우"라는 조건은 **집합(Set)으로 상태를 표현**하면 중복이 자동으로 제거된다.
- 후보 목록은 **패턴(행) 하나당 하나의 리스트**여야 한다. 매칭될 때마다 따로 추가하면 행이 쪼개져 경우의 수가 틀리게 나온다.
- `states.add(new HashSet<>())`처럼 **빈 집합 하나를 초기 상태**로 넣어 두면 첫 번째 패턴도 같은 코드로 처리할 수 있다. (`states`를 완전히 비워 두면 항상 0이 나온다.)
- `new HashSet<>(set)`으로 **복사본**을 만든 뒤 원소를 추가해야 원본 상태가 오염되지 않는다.
- 집합을 "있다/없다"로 표현할 수 있다면 **비트마스크**로 바꿔 성능과 코드 길이를 줄일 수 있다.
